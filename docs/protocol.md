# Протокол barphone v1

Контракт между агентом на ПК (`agent/`, Go) и приложением-декой на телефоне (`app/`, Flutter).
Любое изменение здесь — сначала в этом файле, потом в коде обеих сторон.

## Порты и интерфейсы

| Что | Адрес | Кто ходит |
|---|---|---|
| LAN API (телефон) | `0.0.0.0:47800`, HTTP + WebSocket | телефон |
| UI настройки | `127.0.0.1:47801`, HTTP | только браузер на этом ПК |

UI настройки слушает только loopback и не доступен из сети.
LAN API не умеет ничего, кроме: отдать публичную информацию о машине, обменять одноразовый код на токен,
отдать состояние деки, отдать иконку и запустить **уже настроенную** кнопку по её `id`.
Путей, команд и аргументов телефон не передаёт никогда.

## Обнаружение (mDNS / DNS-SD)

Сервис `_barphone._tcp.local.`, порт `47800`, TXT-записи:

| Ключ | Пример | Смысл |
|---|---|---|
| `v` | `1` | версия протокола |
| `id` | `5f0c…` | постоянный ID машины (32 hex) |
| `name` | `Рабочий ПК` | отображаемое имя |
| `os` | `windows` / `macos` | ОС |

mDNS — удобство, а не требование: сопряжение по QR работает и без него
(гостевой Wi-Fi и часть роутеров режут multicast).

## Сопряжение

1. В UI настройки нажимают «Подключить телефон». Агент создаёт одноразовую сессию:
   6-значный `code`, живёт **5 минут**, после **5 неверных попыток** сгорает. Одновременно активна одна сессия.
2. UI показывает QR и код. Содержимое QR — URI:

   ```
   barphone://pair?v=1&id=<machineId>&name=<urlenc name>&os=windows&port=47800&code=123456&ip=192.168.1.10,10.0.0.5
   ```

   `ip` — все частные IPv4 машины, первыми идут «физические» адаптеры (Wi-Fi/Ethernet),
   последними — виртуальные (Hyper-V, WSL, VPN). Телефон пробует их параллельно через `GET /api/v1/info`
   с таймаутом ~1.5 с и берёт первый ответивший, у которого совпал `id`.
3. Ручной вариант: телефон нашёл машину через mDNS, пользователь вводит 6 цифр с экрана ПК.
4. Телефон отправляет:

   ```http
   POST /api/v1/pair
   Content-Type: application/json

   {"code": "123456", "deviceId": "<uuid телефона>", "deviceName": "Pixel 8"}
   ```

   Ответы:
   - `200 {"token": "<base64url, 32 байта>", "machine": {"id": "...", "name": "...", "os": "windows"}}`
   - `403 {"error": "bad_code"}` — неверный код
   - `410 {"error": "no_session"}` — сессии нет / истекла / сгорела
   - `400 {"error": "bad_request"}`

   Агент хранит только `sha256(token)`. Повторное сопряжение с тем же `deviceId` заменяет старый токен.
   После успешного сопряжения сессия закрывается.

## Публичная информация

```http
GET /api/v1/info
→ 200 {"v": 1, "id": "...", "name": "...", "os": "windows"}
```

Без авторизации. Используется для проверки адреса и идентичности машины.

## Авторизация

Все остальные запросы LAN API — с заголовком `Authorization: Bearer <token>`.
Неверный/отозванный токен → `401 {"error": "unauthorized"}`; телефон помечает машину «нужно заново подключить».

## WebSocket

```http
GET /api/v1/ws?features=windows
Authorization: Bearer <token>
```

`features` — через запятую, что умеет телефон. `windows` — умеет показывать выбор окна
(`action: choose`). Без него агент при нескольких открытых окнах просто запускает приложение,
как раньше, чтобы старое приложение не получало ответов, которых не понимает.

Сообщения — JSON-объекты с полем `type`. Keepalive — WebSocket ping/pong фреймы,
телефон шлёт ping каждые 10 с; сервер закрывает соединение без входящих фреймов дольше 30 с.

### Сервер → телефон

**`state`** — полное состояние. Приходит сразу после подключения и при каждом изменении
(правка деки на ПК, новый запуск, переименование машины):

```json
{
  "type": "state",
  "machine": {"id": "5f0c…", "name": "Рабочий ПК", "os": "windows", "macs": ["a4:bb:6d:12:34:56"]},
  "deck": {
    "columns": 3,
    "buttons": [
      {"id": "b_k3j2", "title": "Telegram", "kind": "app", "icon": "9f86d081884c7d65"},
      {"id": "b_x91a", "title": "Отчёты", "kind": "path", "icon": null}
    ]
  },
  "profiles": [
    {"id": "default", "name": "Основной", "columns": 3, "buttons": [ … ]},
    {"id": "p_3fa1", "name": "VS Code", "columns": 4, "buttons": [ … ]}
  ],
  "activeProfile": "default",
  "recent": [
    {"id": "b_k3j2", "at": "2026-10-06T14:31:05Z"}
  ]
}
```

**Профили.** На ПК может быть несколько дек: `default` («Основной», есть всегда, идёт первым) и профили,
привязанные к приложениям. Агент следит, какое приложение впереди на ПК, и сам выбирает
`activeProfile` — первый профиль, привязанный к этому приложению, иначе `default`. Панель задач,
«Пуск», поиск, Alt+Tab, экран блокировки и сам агент выбор не меняют.

- `deck` — дека активного профиля: приложения, не знающие о профилях, просто показывают её.
- `profiles` — все профили, чтобы телефон мог закрепить любой (закрепление хранится только на телефоне).
  Если `activeProfile` нет в списке — показывать `default`; если поля `profiles` нет (старый агент) —
  считать `deck` единственным профилем `default`.
- ID кнопок уникальны во всех профилях: телефон может нажать кнопку любого профиля.
- Привязки к приложениям (`apps`) и то, какое приложение впереди, телефону не передаются.
- `state` рассылается только при реальном изменении (переключение между непривязанными приложениями
  телефонам ничего не шлёт).

- `deck.columns` — сколько плиток помещается вдоль короткой стороны телефона: в портретной ориентации это
  колонки, в альбомной — строки (колонок столько, сколько влезает). Лишние кнопки — на следующие страницы
  горизонтально.
- `buttons[].kind` — `app` | `path` | `url` | `keys` (сочетание клавиш) | `text` (ввод текста) |
  `system` (медиа, громкость, питание) | `folder` (папка) | `macro` (цепочка действий). Цель кнопки (путь, сочетание, текст) телефону
  не передаётся. Незнакомый тип — обычная плитка; агент ответит на её нажатие `unsupported`.
- `buttons[].buttons` — у папки (`kind: "folder"`): её кнопки, в том же формате. Папка в папке не бывает.
  Папку телефон открывает сам, без запроса к агенту; кнопки внутри нажимаются по `id`, как обычные,
  и попадают в `recent`.
- `macro` — для телефона обычная кнопка (`glyph: "macro"`). На `launch` агент запускает шаги
  по очереди в фоне и сразу отвечает `done`; пока выполняется другой макрос — `busy`. Шаги (что именно
  запускается и печатается) телефону не передаются. Уже открытое приложение в шаге выводится вперёд
  (без выбора окна и без сворачивания).
- `buttons[].icon` — хэш иконки или `null` (иконка ещё извлекается или её нет — придёт следующим `state`). Иконка не меняется, пока не меняется хэш → кэшировать навсегда.
- `buttons[].glyph` — встроенная картинка для кнопок без иконки: `keys`, `text`, `folder`, `macro` или id системного действия:
  `media_play_pause`, `media_next`, `media_prev`, `media_stop`, `volume`, `volume_up`, `volume_down`, `mute`,
  `lock`, `sleep`, `display_off`, `shutdown`, `restart`. Неизвестное имя — показать букву.
- `buttons[].control: "slider"` — кнопка-ползунок (громкость): тап — как обычно (вкл/выкл звук),
  удержание и ведение пальцем — запросы `volume`.
- `buttons[].confirm: true` — перед нажатием спросить пользователя и прислать `launch` с `confirmed: true`
  (выключение, перезагрузка). Без этого агент отвечает `confirm_required` — так старое приложение,
  не знающее про подтверждение, не может выключить ПК одним тапом.
- `recent` — история запусков **с деки**, новые первыми, без дублей, максимум 12.
  Ссылается на `buttons[].id`; удалённые кнопки агент из `recent` выкидывает сам.
- `machine.macs` — MAC-адреса физических адаптеров для Wake-on-LAN. Поле может отсутствовать.

**`result`** — ответ на `launch` / `focus` / `windows` / `minimize` / `volume`:

```json
{"type": "result", "req": "r17", "ok": true, "action": "launched"}
{"type": "result", "req": "r17", "ok": true, "action": "focused"}
{"type": "result", "req": "r17", "ok": true, "action": "minimized"}
{"type": "result", "req": "r17", "ok": true, "action": "choose",
 "windows": [{"id": "919836", "title": "barphone", "active": true}, {"id": "1247566", "title": "AOv5"}]}
{"type": "result", "req": "r18", "ok": false, "error": "not_found"}
```

- `action`: `launched` — запущено; `focused` — открытое окно выведено вперёд;
  `minimized` — окно приложения было впереди и свёрнуто (повторное нажатие) или ответ на `minimize`;
  `choose` — у приложения открыто несколько окон, ничего не сделано, телефон показывает выбор;
  `windows` — ответ на запрос `windows`; `done` — выполнена кнопка `keys`/`text`/`system`;
  `volume` — ответ на запрос `volume`. Старые агенты `action` не присылают — считать `launched`.
- `windows` — окна приложения кнопки, сверху самое недавнее активное; общий хвост заголовков
  (« - Visual Studio Code») агент уже отрезал. `id` непрозрачный, годится только для `focus`/`minimize`.
  `active: true` — это окно сейчас впереди на ПК и не свёрнуто (у остальных поле отсутствует).
- `value` (0..1) и `muted` — громкость ПК: в ответе на `volume` и на тап по кнопке-ползунку
  (тап переключает «без звука», телефон показывает новое состояние).
- `error`: `not_found` (нет такой кнопки), `launch_failed` (ОС не смогла запустить),
  `window_gone` (окно закрыто или не принадлежит этой кнопке), `confirm_required` (нужно `confirmed: true`),
  `unsupported` (действие не поддерживается на ОС этого компьютера), `busy` (ещё выполняется другой макрос),
  `bad_request`.
- Блокировка, сон, выключение экрана, выключение и перезагрузка выполняются через ~0,4 с после ответа,
  чтобы `result` успел дойти до телефона.

### Телефон → сервер

**`launch`** — нажать кнопку:

```json
{"type": "launch", "req": "r17", "id": "b_k3j2"}
{"type": "launch", "req": "r19", "id": "b_k3j2", "new": true}
{"type": "launch", "req": "r22", "id": "b_off1", "confirmed": true}
```

Кнопки `keys` и `text` нажимают клавиши / вводят текст в окно, активное на ПК в этот момент.

Без `new`: окон приложения нет → запуск; одно → переключение на него, а если оно уже впереди —
сворачивание (`minimized`), так кнопка работает как переключатель; несколько → `choose`.
С `new: true` (или если у кнопки на ПК выбрано «Всегда запускать новое») — всегда новый запуск.
`req` — произвольная строка от телефона, возвращается в `result`.

**`focus`** — переключиться на окно из списка `choose`/`windows`:

```json
{"type": "focus", "req": "r20", "id": "b_k3j2", "window": "1247566"}
```

Агент принимает только окно, которое сейчас принадлежит приложению этой кнопки.

**`windows`** — только список окон, ничего не запуская (долгое нажатие на плитку):

```json
{"type": "windows", "req": "r21", "id": "b_k3j2"}
```

Ответ всегда с массивом `windows` (возможно пустым). Поиск окон есть только на Windows:
на macOS список пуст, а `open -a` и так выводит запущенное приложение вперёд.

**`minimize`** — свернуть окно из списка `choose`/`windows` или, без `window`, все окна приложения:

```json
{"type": "minimize", "req": "r25", "id": "b_k3j2", "window": "919836"}
{"type": "minimize", "req": "r26", "id": "b_k3j2"}
```

Ответ `action: "minimized"`; `window_gone`, если сворачивать нечего; `unsupported` на macOS.

**`volume`** — громкость через кнопку-ползунок (только кнопки с `control: "slider"`):

```json
{"type": "volume", "req": "r23", "id": "b_vol"}
{"type": "volume", "req": "r24", "id": "b_vol", "value": 0.55}
```

Без `value` — прочитать, с `value` — установить (и снять «без звука»). Ответ: `action: "volume"`,
`value`, `muted`. Телефон шлёт не больше одного запроса одновременно, промежуточные значения пропускает.

`recent` пополняется при `launched`, `focused` и `done`; `choose`, `windows`, `minimized` и `volume`
историю не меняют.

## Иконки

```http
GET /api/v1/icon/<hash>.png
Authorization: Bearer <token>
→ 200 image/png (256×256, прозрачный фон)
```

`hash` — первые 16 hex-символов `sha256(png)`.

Для кнопок-ссылок (`kind: "url"`, http/https) агент сам скачивает иконку сайта: самую крупную
из `<link rel="icon">` / `apple-touch-icon` страницы, иначе `/apple-touch-icon.png` или `/favicon.ico`.
Не получилось (сайт недоступен, нужен вход, своя схема вроде `steam://`) — `icon: null`,
телефон рисует значок-глобус.

## Wake-on-LAN

Агент не участвует: телефон запоминает `machine.macs` из последнего `state` и для офлайн-машины
шлёт magic packet (UDP broadcast, порт 9) из той же сети.

## UI настройки (локальный, не часть контракта с телефоном)

Только `127.0.0.1:47801`. Защита от вызова из чужих сайтов в браузере пользователя:
агент проверяет `Host` (только `127.0.0.1:47801` / `localhost:47801` — против DNS rebinding),
а все изменяющие запросы требуют заголовок `X-Barphone-UI: 1` (кросс-доменный запрос с ним
требует CORS preflight, на который агент не отвечает).
